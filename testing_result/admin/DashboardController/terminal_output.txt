## 2. Masalah utama

- **Akses data langsung dari controller — prioritas tinggi.** Controller terlalu mengetahui detail sumber data, sehingga meningkatkan coupling dan menyulitkan pengujian, perubahan database, atau penggantian mekanisme penyimpanan.
- **Logika kemungkinan terlalu padat.** Halstead Volume 2886,33 mengindikasikan banyak operand/operator atau detail implementasi dalam ruang kode yang kecil.
- **Duplikasi kode.** Satu baris berulang tetap perlu dikonsolidasikan agar perubahan tidak harus dilakukan di beberapa lokasi.
- **Ketergantungan antar-komponen masih cukup tinggi.** Nilai coupling/reusability menunjukkan peluang untuk memperjelas batas tanggung jawab dan kontrak antar-layer.
- **Belum ada indikasi masalah besar pada ukuran struktur.** Tidak ditemukan long method atau large class, sehingga refactoring tidak perlu berfokus pada pemecahan kelas besar.

## 3. Rekomendasi architectural refactoring

- **Terapkan pola Controller–Service–Repository/DAO.**
  - Controller menangani request, validasi awal, dan response.
  - Service menangani aturan bisnis.
  - Repository/DAO menangani akses data.
- **Gunakan Repository atau Data Access Abstraction.** Sembunyikan detail query, ORM, atau sumber data dari controller.
- **Tambahkan DTO atau View Model.** Pisahkan struktur data eksternal/API dari model persistence agar perubahan database tidak langsung memengaruhi controller.
- **Terapkan Dependency Inversion.** Komponen bisnis bergantung pada interface/kontrak, bukan implementasi akses data konkret.
- **Ekstrak logika padat menjadi komponen berfokus tunggal.** Pisahkan validasi, transformasi data, kalkulasi, dan orkestrasi proses jika saat ini tercampur.
- **Konsolidasikan kode duplikat.** Pindahkan baris atau perilaku berulang ke helper, utility, service bersama, atau konstanta terpusat sesuai konteksnya.
- **Kurangi ketergantungan antar-layer.** Hindari controller memanggil banyak komponen infrastruktur secara langsung; gunakan service sebagai titik orkestrasi.
- **Tambahkan pengujian pada boundary layer.** Fokus pada unit test untuk service dan repository contract test untuk memastikan refactoring tidak mengubah perilaku.

## 4. Prioritas rekomendasi

### Prioritas 1 — Tinggi
1. Pisahkan akses data langsung dari controller melalui **Service dan Repository/DAO**.
2. Terapkan **abstraksi interface dan dependency inversion**.
3. Identifikasi serta pecah logika dengan Halstead Volume tinggi.

### Prioritas 2 — Sedang
4. Perkenalkan DTO/View Model untuk mengurangi kebocoran detail persistence.
5. Konsolidasikan satu baris kode yang terduplikasi.
6. Tambahkan pengujian pada service dan repository sebelum refactoring lanjutan.

### Prioritas 3 — Pemeliharaan
7. Dokumentasikan tanggung jawab setiap layer dan aturan dependensinya.
8. Pantau Maintainability Index, coupling, dan duplikasi pada perubahan berikutnya.
9. Pertahankan kompleksitas siklomatik tetap rendah dan hindari penambahan logika bisnis di controller.
